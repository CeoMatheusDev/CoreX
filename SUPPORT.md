## Dúvidas e problemas

Use o GitHub Issues para dúvidas técnicas reproduzíveis, bugs e propostas de melhoria. Ao abrir uma issue:

- descreva o resultado esperado e o observado;
- informe sistema operacional, arquitetura e versão exata do Zig;
- inclua commit/branch e comandos executados;
- anexe logs relevantes, removendo caminhos privados, tokens e dados sensíveis;
- forneça um exemplo mínimo quando possível.

Para vulnerabilidades, não abra issue pública. Siga a [Política de segurança](SECURITY.md).

## O que não é suporte garantido

O projeto está em desenvolvimento inicial. Não há garantia de suporte a builds antigos, APIs gráficas ainda não implementadas, plataformas fora de Windows/Linux ou componentes marcados como planejados/experimentais.

Issues não substituem consultoria, suporte comercial ou compromisso de prazo. Seja específico e respeitoso; relatórios bem delimitados são mais fáceis de investigar.
